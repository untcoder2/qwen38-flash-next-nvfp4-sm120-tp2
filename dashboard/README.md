# Kimi Token Ops — локальный токен-дашборд

Статистика токенов по wire-логам Kimi Code, живому инферу SGLang (`192.168.2.127:1234`)
и оценкам стоимости. Чистые HTML/CSS/JS + Python 3, без сборки и без сервера:
данные страница читает из `data.js`, который генерирует `refresh.py`.

Единственный источник истины по схемам данных, владению файлами и техрамкам —
[CONTRACT.md](CONTRACT.md).

## Как открыть

Двойной клик по **`Dashboard.bat`** — он обновляет данные и открывает
`index.html` в браузере по умолчанию. Либо вручную: дважды кликните
`index.html` (или откройте `file:///D:/llm/dashboard/index.html`).

> Страница работает только с локальными файлами (`file://`), интернет нужен
> лишь на ECharts с CDN — без него показывается баннер, а остальное работает.

## Как обновить данные

Данные не подтягиваются сами — `data.js` это снимок на момент генерации
(«обновлено N мин назад» в статус-баре). Чтобы пересобрать:

```bat
cd /d D:\llm\dashboard
python refresh.py
```

или просто заново запустить `Dashboard.bat`. `refresh.py` вызывает
`collect_wire`, `collect_server`, `collect_costs` как Python-модули; упавший
коллектор не ломает остальные — его секция берётся из предыдущего
`data/*.json`, а если и его нет — заполняется пустой по схеме. Итог пишется в
`data.js` атомарно (temp + `os.replace`), так что «полупустой» файл
в середине записи получить нельзя.

## Как изменить окно (window_days)

По умолчанию собирается статистика за **30 дней**. Варианты:

- разово: `python refresh.py --days 7` (или `--days 0.5` — часы тоже можно);
- навсегда: поменяйте `DEFAULT_DAYS` в начале `refresh.py`.

Число уходит в `window.DASH.window_days`, коллекторы получают его аргументом
`days`.

## Дисклеймер про цены

Оценки в секции «стоимость» **приблизительные**: тарифы захардкожены в
`collect_costs.py` и могут отставать от реальных прайс-листов провайдеров;
кэш-вход считается по **замеренному серверному hit-rate** (SGLang ~98,7%:
попадание в radix-кэш = то, за что облако взяло бы кэш-тарифом, в ~10 раз
дешевле входа), остаток prompt — полным входным тарифом; локальная оценка —
огрубление «2×RTX PRO 6000 ≈ 700 Вт × 10 ₽/кВт·ч × активные дни» без учёта
простоя, амортизации и прочей инфраструктуры. Используйте цифры как порядок
величины, не как бухгалтерию.

## Режим «на сервере» (основной с 09.10)
Дашборд размещён на GPU-хосте: **http://192.168.2.127:8090/** (каталог /home/molochko/dashboard).
- полный пересбор `data.js` — cron в 10:00 и 20:00 (refresh.py: wire-пуш + метрики + цены);
  накопительные серверные счётчики тикают каждые 30 мин (`tick_counter.py`) и переживают
  рестарты инфера (baseline в `data/server_state.json`, детект по `docker inspect penny`);
- единственное, чего сервер сам не может — wire-логи Kimi Code живут на Windows:
  их доносит `ops/push_wire.py` (или двойной клик `Dashboard.bat`: пуш → внешний refresh → открыть страницу);
  протухший пуш старше 7 суток — проектная разбивка деградирует в нули, остальное живое;
- watchdog http-сервера и рестарт после reboot — тоже cron (@reboot + */5, serve-dashboard.sh);
- локальная копия в D:\llm\dashboard по-прежнему открывается через file:// без сервера.
