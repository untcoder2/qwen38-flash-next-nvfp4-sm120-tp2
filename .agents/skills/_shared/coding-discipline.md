# Продюсерский кодекс написания кода (D:*)

Обязателен coder-ролям при любой правке кода; проверяется парой code-review/security-review по ID и арбитром по вердиктам с ID. Идеи — unclebob/ub-mode (27.10.2026), переформулировано под наш стек; это не копия текста.

## Правила

- **D:PREMISE** — стоп-кран петли: две правки с общим предположением провалили один и тот же гейт ⇒ сформулируй предположение одним предложением, назови, кто держит перекос, убери назначение и пересмотри. Третья правка не начинается до этого.
- **D:SUBTRACT** — перед добавлением убери: мёртвые ветки, второй слой того же решения, конфиг-дубли. Если фича выражается удалением кода — выражай её так.
- **D:ONE** — одно решение живёт ровно в одном месте; второе место того же решения — дефект, даже пока согласованный. Запланированный минимальный патч, а не «заодно».
- **D:SHAPE** — сначала форма данных, потом логика. Делай первым то, что помогает всем последующим фазам.
- **D:LEVER** — работа повторяется и не очевидна на глаз: выполни один юнит руками, потом сделай инструмент, воспроизводящий юнит (rsh/runsh — эта схема).
- **D:BOLT** — не приваривай новое требование к старому дизайну: реши, что строил бы при исходном требовании, доставляй проверяемыми кусками.
- **D:BOUNDARY** — проверяй данные на входе, внутри доверяй; бизнес-логика чистая, нисыки на границе.
- **D:IDEMP** — повторная операция и операция после полукраша дают то же состояние (retry, рестарт юнита, вотчдог).
- **D:STATE** — не делят mutable без нужды; делят — один writer, закреплено структурой, а не договорённостью.
- **D:TEST** — тест проверяет поведение через интерфейс пользователя; тест, прошедший когда все функции вернули пустоту, — мусор. Нечестный тест не пишется взамен отсутствующего честного.

## Самоотчёт

Handoff coder-агента содержит строку `discipline:` — по каждому ID в формате
`ID=статус:доказательство` (file:line или одна фраза факта). Статусы: `ok` — правило
применимо и соблюдено, без доказательства приравнивается необоснованному заявлению;
`n/a` — правило неприменимо к типу изменения; `нарушено` — чем и почему.
Завышение (ok при фактическом нарушении) = FAIL-уровень несоответствия самоотчёта.
Безобидная неточность (ok там, где строже n/a) обязана быть видна: ревьюер обязан
вывести строку `discipline-audit:` в гейт-отчёте с перечём расхождений. Признанное
нарушение = FIX-FIRST; скрытое = находка второго раунда.

## Вне кодекса

Ворота crapper/dryer/mutator не подключены: стек — python/bash/JS-зеркала и ops-скрипты. Детерминированную часть судейства несут PostToolUse py_compile/bash -n, гейт-пара и арбитр.
