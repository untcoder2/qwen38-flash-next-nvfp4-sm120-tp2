# Разведка веб-поверхности

До использования инструментов прочитай [среду проекта](${KIMI_SKILL_DIR}/../_shared/llm-environment.md); она уточняет место исполнения и не расширяет разрешения.

Результат — карта активов, путей, параметров и технологий с происхождением и статусом подтверждения. Прочитай правила проекта, используй данное разрешение и зафиксируй scope. Разведка не разрешает эксплуатацию.

1. Пассивно: DNS/сертификаты/публичные документы/репозитории/архивы. Отмечай исторические endpoints; не выдавай их за текущие. Упоминание утёкших credentials фиксируй обезличенно, не используй их без разрешения.
2. Активы: subfinder или amass passive, затем разрешённая DNS/HTTP-проверка обнаруженных in-scope имён. Редирект, CDN-сосед или внешняя ссылка не расширяют scope.
3. Технологии: HTTP-метаданные, whatweb/ProjectDiscovery httpx, JS и API-документация. Различай наблюдаемую версию и предположение.
4. Пути/параметры: адресные словари из структуры приложения, JS routes и API-версии; ffuf или эквивалент. Сначала измерь обычный ответ и wildcard/soft-404 на нескольких отсутствующих путях; фильтруй по проверенному baseline и вручную подтверждай значимые попадания.

## До активного шага

Выбери и запиши число запросов/сек, параллелизм, общее время и правила остановки по ошибкам/rate limit; соблюдай ограничения проекта. Вывод и словарь ограничивай задачей. Не запускай неограниченный перебор по умолчанию.

Проверь команду и версию. CLI ProjectDiscovery httpx — не Python-библиотека httpx; одинаковое имя не доказывает наличие нужного инструмента. Значения TARGET, словарь и baseline должны быть определены до запуска, а не оставлены shell-плейсхолдерами.

Пример формы ограниченного запуска после выбора переменных:
```bash
ffuf -u "$TARGET/FUZZ" -w "$WORDLIST" -rate "$RATE" -t "$THREADS" -maxtime "$MAX_SECONDS" -o "$OUT_JSON"
```
Это шаблон аргументов, не разрешение его выполнить. Не устанавливай инструменты в общую среду молча.

## Карта

Для host/path/parameter укажи источник, live/historical/непроверен, статус, tech, auth и заметные экспозиции. Группируй endpoints по auth/API/admin/upload/static. Возможный ключ показывай замаскированным. Передай карту в pentest или security-review только если следующий этап входит в запрос; иначе заверши на карте.
