# Контракт отката GPU-стенда (pennyroyal/SGLang на GPU-HOST)

Цель: откат обязан быть предсказуемым и проверяемым ДО рестарта, а не «после
рестарта оказалось, что не на что откатывать». Действует для всех изменений:
образ, serve-скрипты, конфиги модели, chat template, генерационные дефолты.

## Правила

1. **Только снапшоты, никаких .bak-рядом-с-файлом.** Единственный источник
   отката — каталог снапшотов. Разбросанные .bak (включая *.bak.pledtype) —
   мусор-память, по ним НЕ откатываемся.
2. **Образ фиксируется digest'ом, не тегом.** `docker tag <imageID>
   rollback:keep-<id>` перед любым изменением; prune-политика: rollback-теги
   не удалять (включить в исключения / запретить `image prune -a` на хосте).
3. **Снимок = состояние работающего процесса, а не скрипта.** Флаги серва
   пишутся из `/proc/<docker-run-pid>/cmdline` и `/proc/<sglang-pid>/cmdline`
   (дубли аргументов: последний выигрывает — фиксируем как есть, победителя
   отмечаем).
4. **Все файлы — под sha256.** Модельные конфиги (config.json,
   hf_quant_config.json, generation_config.json, chat_template.jinja,
   model.safetensors.index.json, *.sh serve-семейки) заносятся в манифест с
   хешем; крупные safetensors — отдельным списком «проверить, не трогали ли»
   (полное хеширование ~126 ГБ — по запросу).
5. **Откат исполняется атомарным скриптом с гейтами и завершается валидацией,
   которую надо ПРОЧИТАТЬ, а не «сервер поднялся — ок».**

## Структура снапшота

    /home/OPERATOR/penny/snapshots/<UTC-время>--<метка>/
      MANIFEST.json      # imageID+RepoDigests, /proc cmdline, env, список файлов с sha256
      files/             # копии малых файлов: serve-скрипты, конфиги модели, template
      smoke/GOOD-<метка> # маркер «эта конфигурация прошла валидацию» (пишет verify)

Мини-копия MANIFEST.json (только текст) зеркалится в
`D:\llm\docs\server-snapshots\` — чтобы представление о «хорошем» жило не
только на GPU-хосте.

## Скрипты (разворачиваются на хост при первом применении)

- `snapshot.py [--label before-update-2.5.1]` — собирает снапшот (правила 2–4).
  Требует --rm контейнер penny запущенным; сверяет, что записанные cmdline
  совпадают с аргументами скриптов penny/, расхождения печатает явно.
- `rollback.py <снапшот>` — стоп контейнер через точку переключения
  (serve-penny.sh, НЕ docker kill в обход) → `sha256sum -c` манифеста против
  ТЕКУЩИХ файлов (показать, что именно разъехалось — перед перезаписью!) →
  восстановление файлов из files/ → установка image по digest из MANIFEST →
  старт → `verify.py <снапшот>`.
- `verify.py <снапшот>` — гейты (см. ниже), пишет smoke/GOOD.

## Валидация после рестарта (гейты, все обязательны)

1. `/get_server_info`: model_path, `sampling_defaults=model`,
   `default_chat_template_kwargs` — совпадают с MANIFEST (это ловушка:
   effort/темпы живут в аргументах запуска, а не в файле модели).
2. `/v1/models`: сервимя модели; `/metrics`: sglang-счётчики начнут расти (не пустой выхлоп).
3. `generation_config.json` на диске == хеш из манифеста (temp 1.0/top_p 0.95/top_k 20).
4. Функциональная: 1 короткая генерация (проверка reasoning-ветки: при
   reasoning_effort=xhigh думать больше, чем low — по токен-счётчику запроса),
   bogus-proба `chat_template_kwargs.reasoning_effort=bogus` → ожидание 400
   «Unexpected reasoning effort» (значит шаблон на месте).
5. `_uptime.py <контейнер>`: accept медиана ≥ 2.0, retract == 0.
6. Качество: `_quality.py` (20 задач, проверяемые ответы) — 20/20.
   Проход: `tool_call` smoke (массив из 3 вызовов — парсер qwen3_coder жив).

Любой непройденный гейт = состояние «откат НЕ завершён», сервер не
публикуется как рабочий; разбор по факту вывода, не повторением запуска.

## Известные ловушки этого стенда (почему «не откатывается»)

| Ловушка | Механизм | Противоядие из контракта |
|---|---|---|
| `docker image prune` сожрал старый образ | 26.7 ГБ/образ, диск-давление | digest-пин rollback:keep + запрет `-a` |
| Откатили скрипт, а крутится другой набор флагов | дубли аргументов, «последний wins»; скрипты менялись на живую (семь .bak) | снимок из /proc cmdline; откат=старт из снапшота, не «починка скрипта» |
| .bak-рядом перезаписан следующим прогоном | имена с накатом, нет привязки к запуску | правило 1: только снапшоты; .bak не трогаем вообще |
| Правка конфига модели без понимания какой версии | config.json/.bak.pledtype в одном каталоге | sha256-манифест + verify ДО объявления отката завершённым |
| Сервер «поднялся» ≠ «поднялся правильно» | sleep-on-idle маскирует деградацию | гейты 1–6, чтение вывода, а не наличия порта |
| Двойной старт при ручном рестарте | penny сидит на systemd (`sglang.service`, Restart=always) + dispatcher `serve-active.sh` читает `active.cfg` -> лист `serve-penny.sh`; отдельный `setsid serve-penny.sh` воюет с авторестартом юнита (проверено 19.09 при апдейте 2.5.1) | рестарт ТОЛЬКО `systemctl restart sglang.service`; rollback.py так и делает |

## Реальная топология супервизора (уточнено 19.09)

    sglang.service (systemd, Restart=always)
      -> /home/OPERATOR/vllm/serve-active.sh (dispatcher)
           -> читает /home/OPERATOR/vllm/active.cfg (дефолт serve-fn-off.sh!)
           -> exec /home/OPERATOR/vllm/<активный лист>.sh (сейчас serve-penny.sh; мьютекс одиночного запуска — в листах)
                -> docker run --rm --name penny  (образ — из листа, не из юнита!)
    Параллельно: watch-vllm.sh умеет запускать листы напрямую (источник сценариев «два супервизора»).

Следствия: `docker stop penny` без остановки юнита = гонка рестарта; правки образа —
в листе (`serve-penny.sh:34`); `_quality.py` сам дёргает `systemctl restart` и переключает
spec через свой SH-скрипт — после него проверять `active.cfg` и образ контейнера.

## Порядок применения к ближайшему апдейту v2.5.0 → v2.5.1

1. До любых действий: `snapshot.py --label v2.5.0-golden` (и дописать в
   MANIFEST «smoke/GOOD» — стенд сейчас валиден по гейтам 1–5, 6 не проходил с
   последнего изменения — прогнать перед снапшотом).
2. docker pull v2.5.1 (уже идёт) — к живому сервису не касается.
3. Правка точки переключения (serve-penny.sh: тег) + запланированная чистка
   mtp.* из hf_quant_config.json (каждое — отдельным шагом с verify).
4. Рестарт через супервизор → verify.py → только потом докладывать «готово».
   Откат = `rollback.py v2.5.0-golden` — один шаг, без угадывания.
