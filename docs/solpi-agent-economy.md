# Чек-лист агентской экономии (адаптация NVlabs/SoL-Pi под наш стек)

> Первоисточник: [NVlabs/SoL-Pi](https://github.com/NVlabs/SoL-Pi) ([nvlabs.github.io/SoL-Pi](https://nvlabs.github.io/SoL-Pi/)), arXiv 2609.20519, MIT.
> NVIDIA автоисследованием (152 идеи → 4 выживших механизма, ~1/40 конверсия) показало: на длинных агентных
> прогохах −45…64% токенов и −50% стоимости при лист-прайсе, качество ≈94% базового габа.
> Это расширение для габа Pi; в Kimi Code не ставится — ниже правила, переносимые в поведение агентов.
> Железо-уточнение: сервер = 2×RTX PRO 6000; 5090 — отдельный комп, не сервер.

## Четыре механизма (наш аналог каждого)

**1. Action Fusion — «одно намерение, один ход».**
Правка файла и её предсказуемая проверка (py_compile / bash -n / тест / grep) выполняются ОДНИМ tool-вызовом:
`Edit` сразу с прогоном валидации через `&&`, без лишнего round-trip «а теперь проверь».
- Правило: любая правка кода на Windows-зеркалах и скрипты на хосте — всегда с проверкой в том же вызове.
- Из их «кладбища идей»: T9 — батчить ожидания/повторы; T5 — детерминированные последовательности одной `run-steps`-командой.

**2. ObservationPack — «ручка вместо повторного мегабайта».**
Большой вывод инструмента (логи, ffuf-отчёты, docker logs, wire-дампы) — пишем в файл, в контексте держим
ручку+короткий экзерпт; в последующие запросы не переносим целиком, а достаём точные страницы grep/Read+offset.
- Правило: >2–3КБ результата → файл + ≤10 строк в контекст; повторный «покажи то же» запрещён — только прицельная выборка.
- Их C5/C16: архив неизменяемый, evict старых наблюдений детерминированно, ещё до любого суммаризатора (C9).

**3. Evidence-Preserving Reducer — «квитанция, а не пересказ»**.
Чтение длинных логов/дамп'ов делегируется дешёвому агенту, который обязан вернуть КВИТАНЦИЮ: точные цитаты строк
+ указатели на архив. Доверие к квитанции только после сверки цитат с источником; сверка упала → читаем сырьё.
- Правило для сабагентов-аналитиков: «каждая претензия — с цитатой file:line; без цитаты — не факт».
- Их D6: не делегировать генерацию правок без верификатора; D11: дешёвый «скаут» перед дорогим ревьюером.

**4. Online Context Compact — «компакт по экономике, не по стене».**
Триггеры компакции: (а) завершение подзадачи — семантическая граница, а не паника у лимита; (б) экономическая
проверка: будущая экономия от перезаписи > стоимости самой компакции; (в) «repay» — после компакта прогон должен
окупить rewrite (их M15 платит за разрыв кэша).
- У нас уже стоит: кэрп 850K + reserved 80K (сработало после vpncode-дедлока).
- Новое правило: не трогать системные префиксы (AGENTS.md/скилы/конфиг) ПОСРЕДИ активной сессии — это рвёт radix-префикс
  и превращает дёшевый cache-hit в дорогой miss (их C20 «prompt-cache prefix churn» — главный злодей; у нас 98.9% хитов —
  это и есть аккуратные префиксы).
- Их P22: debounce проверок — не гонять полную валидацию, пока правки идут потоком; гонять на паузе.

## Правила из их «поля 152 направлений», полезные напрямую

- **C12:** после мутации файла — не перечитывать его «для уверенности» целиком; источник истины — diff.
- **C4/P1:** прогресс-контрол по доказательствам: «готово» только с проверочной слекой (fail-before/pass-after, M12);
- **P16:** эскалация — с точной командой воспроизведения, а не «не работает»;
- **R9:** reasoning-effort маршрутизируется по фазе: разведка — дешёвый уровень, решения — xhigh (у нас effort-кэрп 850K + PENNY_REASONING_EFFORT-хелпер это позволяют);
- **D10:** свежий контекст при handoff (research→implement→review) — сабагент, а не раздутый мейн (ими подтверждено и так: рои в мейне дороже);
- **M19:** service-классы затрат — в отдельную «cost lane»: считай билл по workspace (token_bill_days.py — это же и делает);
- **T2:** сначала чини транспорт tool-call'ов, потом поведение (урок SGLANG_FORWARD_UNKNOWN_TOOLS — ровно он).

## Что НЕ делать (антипаттерны, которые они отбросили валидацией)

- «ранний компакт» и «грубая краткость» как механизм (R7) — экономия ценой качества; у нас capability floor = verify-гейты;
- few-shot/RAG/кейворд-гейты как основной рычаг (R12);
- постоянный REPL без доказанной нужды в состоянии (T6); батчить пробы можно, скрывать причинность — нет (T4).

## Протокол для следующего раунда (когда скажешь «го»)

Метрики до/после считаем тем, что уже есть: `token_bill_days.py` (поданные/ген), серверные ReqTimeStats (hit%),
арена-тайминги. Внедряем механизмы 1–3 как правила в скилы (`code-review`, `pentest`, `web-recon`) и в AGENTS.md-секцию
поведения; сравниваем средний prompt-токен/шаг и шагов/задачу за две недели до/после.
