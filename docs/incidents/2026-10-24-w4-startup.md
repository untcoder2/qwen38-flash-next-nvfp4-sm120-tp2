## Причина остановки

В `/home/molochko/penny/tp2-serve-flash-next.sh` строки 142 и 143 одинаковы:

```bash
  --field "speculative_algorithm=NEXTN" \
  --field "speculative_algorithm=NEXTN" \
```

`derive_namespace.py` из закреплённого образа v3.1.1 отклоняет дублирующие
имена полей: `derive_namespace: duplicate field: speculative_algorithm`.
Leaf завершается с кодом 2 до запуска SGLang и загрузки весов.

- 00:09:01: создан `.maintenance`, установлен W4-профиль, селектор переключён
  на `serve-penny-311w4.sh`.
- 00:09:23: первый неудачный старт. Следующие старты повторяют ту же ошибку.
- 00:10:27: systemd прекратил попытки: `Start request repeated too quickly`.
- 03:33: `sglang.service=failed`, `ExecMainStatus=2`, `NRestarts=5`, контейнера
  penny нет, :1234 закрыт; обе GPU по 20 MiB, использование 0%.

Это ошибка сборки W4-профиля; свидетельств падения при вычислениях здесь нет.

## Почему не было отката

1. `sglang.service` делает `Restart=always`, но запускает ту же выбранную
   конфигурацию. Ограничение `StartLimitBurst=5`, `StartLimitIntervalSec=600`.
2. `vllm-watchdog.service` disabled/inactive, однако отдельный `watch-vllm.sh`
   живёт с 29.09 (PID 63464, PPID 1). `.maintenance` заставляет этот процесс
   выполнять только sleep/continue. Без maintenance он также не откатывает:
   читает текущий active.cfg и пытается поднять тот же leaf.
3. `rollback-monitor.sh` не запущен. Последний лог — 16.09. Скрипт устарел:
   HTTP smoke вместо HTTPS, восстановление только active.cfg на
   serve-fn-bf16mtp.sh, без соответствующего профиля. Применять его к текущей
   паре нельзя без переделки.
